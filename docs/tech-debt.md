# Технический долг и MVP-решения

Реестр решений, принятых ради скорости MVP. Каждое сознательно упрощено — здесь
записано, **почему так сейчас**, **когда менять** и **на что**. Не удалять строку,
пока долг не закрыт; при закрытии — перенести в раздел «Закрыто» с датой.

Конвенция в коде: на месте упрощения ставим `// NOTE: MVP — <что>; см. docs/tech-debt.md`.

## Открытые

### 1. JWT в заголовке `Authorization: Bearer`
- **Сейчас:** access-токен хранится фронтом и шлётся в заголовке.
- **Почему:** проще всего для SPA + API, стандартный поток, понятно для обучения.
- **Риск:** токен доступен JS → уязвим к XSS.
- **Менять когда:** появится реальная админка с чувствительными действиями.
- **На что:** httpOnly+Secure cookie + CSRF-защита.

### 2. Без refresh-токена
- **Сейчас:** один access-токен с TTL в несколько часов, по истечении — релогин.
- **Почему:** refresh — это хранилище, ротация, отзыв; много кода ради малого на старте.
- **Менять когда:** менеджерам станет больно перелогиниваться.
- **На что:** пара access (короткий) + refresh (длинный, в БД, с отзывом и ротацией).

### 3. Создание менеджера через CLI
- **Сейчас:** `cmd/createmanager` заводит менеджера руками.
- **Почему:** одна компания, менеджеров единицы; публичной регистрации не нужно.
- **Менять когда:** менеджеры должны заводить менеджеров сами.
- **На что:** защищённая ручка «менеджер создаёт менеджера» поверх существующего CLI.

### 4. Смена статуса лида без стейт-машины
- **Сейчас:** `PATCH /leads/:id` принимает любой статус из enum, переходы не ограничены.
- **Почему:** менеджеру доверяем, в реальных воронках бывают исключения (вернуть из `rejected`).
- **Менять когда:** бизнес-правила переходов станут жёсткими.
- **На что:** явная стейт-машина допустимых переходов.

### 5. CORS `Access-Control-Allow-Origin: *`
- **Сейчас:** `internal/http/router.go` отдаёт `*` всем источникам.
- **Почему:** на этапе разработки фронт и API на разных портах, удобно.
- **Риск:** в проде открывает API любому сайту.
- **Менять когда:** перед первым деплоем.
- **На что:** белый список origin'ов из конфига.

### 6. Калькулятор: формула цены захардкожена на фронте
- **Сейчас:** лендинг считает диапазон цены по константам в JS.
- **Почему:** на MVP важен сам факт «показать вилку и собрать лид», не точность.
- **Менять когда:** появится реальная тарифная логика.
- **На что:** бэкенд-эндпоинт `POST /calc` с тарифами в БД/конфиге.

### 7. Бот: long polling
- **Сейчас:** `go-telegram-bot-api` на long polling.
- **Почему:** работает локально без публичного URL и TLS.
- **Менять когда:** деплой.
- **На что:** webhook.

### 8. Уведомления в единый чат (`MANAGER_CHAT_ID`)
- **Сейчас:** новый лид уведомляет один чат/группу из env.
- **Почему:** пер-менеджерская маршрутизация требует связи manager↔telegram_id, которой ещё нет.
- **Менять когда:** менеджеры авторизуются и привязывают свой Telegram.
- **На что:** рассылка по `telegram_id` из таблицы managers.

### 9. Gin в debug-режиме
- **Сейчас:** `gin.New()` без `ReleaseMode`.
- **Почему:** локально удобны debug-логи.
- **Менять когда:** прод.
- **На что:** `gin.SetMode(gin.ReleaseMode)` по `AppEnv`.

### 10. Dev-дефолт `JWT_SECRET`
- **Сейчас:** `config.go` подставляет `dev-insecure-secret-change-me`, если env пуст.
- **Почему:** удобный локальный старт без настройки.
- **Риск:** с дефолтом в проде любой может подделать токен менеджера.
- **Менять когда:** перед первым деплоем.
- **На что:** падать на старте, если `JWT_SECRET` пуст и `APP_ENV != development`.

### 11. Уведомление о лиде — fire-and-forget в горутине
- **Сейчас:** `LeadService.notifyNewLead` шлёт в отдельной горутине, ошибку только логирует.
- **Почему:** латентность Telegram не должна тормозить ответ клиенту, а сбой бота — ронять заявку.
- **Риск:** при остановке процесса незавершённая отправка теряется; нет ретраев.
- **Менять когда:** уведомления станут критичными (не только лиды).
- **На что:** очередь/воркер с ретраями и graceful shutdown (outbox).

### 12. Отправка в Telegram без таймаута/отмены
- **Сейчас:** `bot.NotifyNewLead` игнорирует `ctx` — библиотека v5 не context-aware.
- **Почему:** простота на MVP.
- **Риск:** зависший запрос блокирует горутину.
- **Менять когда:** заметная доля отправок виснет.
- **На что:** HTTP-клиент с таймаутом / обёртка с `select` по `ctx.Done()`.

### 13. Миграция 000006: индекс в одной миграции с колонкой
- **Сейчас:** `add column lead_id` и `create index` в одном файле.
- **Почему:** одна маленькая аддитивная правка, миграция уже применена (v6), а менять
  применённую миграцию нельзя.
- **Расходится с:** `database.md` («индексы — отдельной миграцией для независимого отката»).
- **Менять когда:** при следующем индексе — выносить отдельно; 000006 не трогаем.

### 14. Кардинальность client.lead_id не зафиксирована
- **Сейчас:** FK без UNIQUE — формально допускает несколько клиентов на один лид.
- **Почему:** полная конверсия в Фазе 3; кардинальность ещё не решена.
- **Менять когда:** в Фазе 3 при создании Client. Если 1:1 — partial unique index
  (`where lead_id is not null`); если 1:N — задокументировать намерение.
